# 首振りLiDARの走行中の点群生成・自己位置推定設計 {#nodding_motion_localization_design}

## 1. 目的と採用基準

直進中も旋回中も、首振りLiDARのスキャンマッチングによる地図上の位置補正を継続する。
旋回中は計測時刻の姿勢で点群を補償し、長時間の蓄積に伴う歪みを抑える。
実機の `nodding_lidar` とシミュレーションが同じ処理を使用できることを採用条件とする。

共通の蓄積ノード、実機とシミュレーションの接続、蓄積幅・欠測・出力遅延の診断を実装する。
機器時刻の同期、サーボ実測角の取得、真値を使う性能評価は採用前の検証項目とする。
測定前に精度・処理周期・連続照合の成功を保証しない。
変更対象は自作パッケージに限り、外部ライブラリと `thirdparty` 以下は変更しない。

対象は車輪とIMUを使うEKF（拡張カルマンフィルター）が局所移動を推定する構成。
`standalone_slam_launch.py` のLiDARだけで移動を推定する構成は対象外とする。
LiDARで求めた姿勢を同じ点群の運動補償に使う循環を避けるため、別の検証が必要である。

## 2. 現在の構成と制約

| 項目 | 実機 | シミュレーション |
|---|---|---|
| 点群生成 | 共通の `scan_to_cloud` | 共通の `scan_to_cloud` |
| スキャン内の点時刻 | スキャン時間などから推定 | GPU LiDARの同時刻計測として扱う |
| サーボ角 | Unoの指令角・指令角速度から推定 | Gazeboの関節位置・速度 |
| サーボ状態の時刻 | PCでCSVを処理したROS時刻 | 関節状態の計測時刻 |
| 局所オドメトリ | `/odometry/local` | `/odometry/filtered` |
| RTAB-Mapの点群入力 | 共通ノードの `/points_matching` | 高さ選別後、共通ノードの `/points_assembled_icp` |
| 点群照合の自由度 | 3次元の位置・姿勢 | 平面の位置・向き |

実機とシミュレーションは蓄積ノードを共用するが、点の選別と照合自由度は一致していない。
比較試験ではこれらも揃え、異なる入力条件のまま実機に有効な改善とは判定しない。

実機の `serial_angle_bridge` はCSVの機器時刻を座標変換に使用していない。
シリアル到着・読出しの遅れと、サーボの指令に対する追従遅れは、
補間精度を上げるだけでは除去できない。受信バッファ内の複数行が近い時刻に
処理される場合もあるため、送信周期とROSのstampの分布を記録する。

LiDARの角度補償による点の並べ替えと `time_increment` の関係も未確定である。
配列を逆順にする設定だけで点時刻が正しくなると仮定しない。
Gazeboの同時刻スキャンによる検証だけでは、実機のスキャン内補償は検証できない。

## 3. 責務とTFの所有者

| 処理・変換 | 担当 | 契約 |
|---|---|---|
| `odom → base_footprint` | 車輪＋IMUのEKF | LiDAR補正を入力せず、連続した局所移動を推定する |
| 車体・センサ取付位置 | 実機の静的TF、シミュレーションのURDF | 同じ寸法・軸・符号を使用する |
| 首振り姿勢 | `/servo_state` とサーボTFの配信元 | 推定角か実測角か、時刻の由来を明示する |
| スキャン内の運動補償 | `scan_to_cloud` | 各ビームの時刻に対応する姿勢・首振り角を使う |
| 複数スキャンの蓄積 | 新設する共通の蓄積ノード | `odom` に保存し、出力基準時刻の `base_link` に戻す |
| 点群照合と `map → odom` | RTAB-Map | 地図作成・自己位置推定の双方で唯一のTF配信元とする |

点群を蓄積する座標系に `map` を使用しない。RTAB-Mapの地図補正が、
照合前の点群を動かすフィードバックを避ける。
サーボ角の補間を点群生成で行う場合、動的サーボTFによる回転を重ねて適用しない。

`adaptive_map_correction` による出力TFの平滑化は比較構成から外す。
RTAB-Map内部の地図とNav2が使う姿勢を異なる補正値にする方式は採用しない。
機能を外す際はRTAB-Mapの `publish_tf` を同時に有効化し、TFの重複・欠落を避ける。

## 4. 時刻とスキャン内の運動補償

ROSの時刻を基準にし、シミュレーションとbag再生では `/clock` に統一する。
計算に使う時刻はメッセージの計測stampであり、コールバックの実行時刻ではない。

ビームiの時刻を `t_i`、スキャン基準時刻を `t_ref` とする。
`T_A_B(t)` は時刻tにB座標の点をA座標へ変換する剛体変換とする。
距離から求めたLiDAR座標の点 `p_laser(i)` を次の順に変換する。

1. `p_odom(i) = T_odom_servo(t_i) × T_servo_laser(phi(t_i)) × p_laser(i)`
2. `p_base(i) = inverse(T_odom_base(t_ref)) × p_odom(i)`

位置の単位はm、角度はrad、時刻と時間差はsとする。
`/points` はスキャンごとに出力し、frameを `base_link`、stampを `t_ref` にする。
現行のスキャン開始時刻を基準にする契約を維持し、開始・終了時刻の解釈は入力側で正規化する。
距離、首振り角、TFが有効なビームだけを使用する。

時刻の扱いは次の3モードを区別する。

| モード | 点時刻の由来 | 使用条件 |
|---|---|---|
| 同時刻 | 全ビームが同じ計測時刻 | Gazeboの同時刻GPUスキャン |
| 推定時刻 | `time_increment` またはスキャン時間から算出 | 実機ドライバとの対応を検証し、診断で推定と表示 |
| 個別時刻 | ドライバが出力する各点の計測時刻 | 対応ドライバ・メッセージ形式を用意した場合 |

既存の `LaserScan` 入力は同時刻・推定時刻を扱う。
個別時刻は将来の入力アダプタの拡張とし、存在しない情報を復元できるとはしない。
スキャン計測の開始・終了時刻、点の並び、ROS時刻への対応を実機ドライバごとに確認する。

サーボはまずPC受信時刻の遅延・ばらつきと追従誤差を測定する。
一定の時間差を補正する場合も、実測に基づく値とし、可変遅延まで補正できるとはしない。
要件を満たさない場合は、機器時刻からROS時刻への変換と再起動・時計のずれの処理、
またはサーボ実測角の取得を別段階で実装する。指令角を実測値として扱わない。

時刻誤差Δt [s]による横ずれの目安は、小角度で `e ≈ r × |ω| × |Δt|` [m]。
例えば距離10 m、角速度0.4 rad/s、時刻誤差0.01 sなら約0.04 mとなる。
これは誤差予算の算定例であり、許容値の確定ではない。首振り角の時刻ずれにも同様の評価を行う。

## 5. 共通の点群蓄積ノード

`motion_cloud_assembler` の実装先は `nodding_lidar` とする。
シミュレーションは同じ実行ファイルを使用し、センサ入出力だけをremapする。
IMUの座標変換・符号処理を二重実装しないよう、蓄積幅の判断にはEKFの
`Odometry.twist.twist.angular.z` を使う。IMU単独の角速度は比較・異常診断に使用する。
IMUを優先する度合いはEKF側で検証し、蓄積ノードで姿勢を別に積分しない。

### 入出力

| 入出力 | 型・単位 | 内容 |
|---|---|---|
| 入力 `cloud` | `PointCloud2` | スキャン内補償済みの単発点群。frameは `base_link` |
| 入力 `odometry` | `Odometry`、m・rad・m/s・rad/s | 独立した車輪＋IMUの推定。twistは指定した車体フレームに対応 |
| 入力TF | `odom ↔ base_link` | 入力点群のstampを含む履歴 |
| 出力 `matching_cloud` | `PointCloud2` | RTAB-Mapへ渡す点群。frameは `base_link` |
| 出力 `diagnostics` | `DiagnosticArray` | 蓄積幅、角度変化量、点数、遅延、欠測、棄却理由 |

生の `/points` を維持し、蓄積点群で上書きしない。
RTAB-Mapは点群のstampに対応するEKFオドメトリと同期して入力する。
出力点群のstampだけを現在時刻へ書き換えることは禁止する。

### 蓄積の規則

入力点群を計測時刻のTFで `odom` へ変換して保存する。
最新の入力スキャンの基準時刻を出力基準時刻とし、その時刻の `base_link` へ変換して出力する。
点群を正しく補償した上で窓を短くする。窓短縮を姿勢補償の代用としない。

点群の保持範囲は次のすべてを満たす移動窓とする。

- 最大蓄積時間 `max_window_s` [s]以内。
- 蓄積した時刻間の絶対角速度の積分 `∫|ω_z|dt` が `max_turn_span_rad` [rad]以内。
- メモリ上限として最大スキャン数・最大点数以内。

角速度が大きい場合、目安の時間幅は `max_turn_span_rad / |ω_z|` [s]となる。
左旋回と右旋回が相殺されないよう、最初と最後の向きの差だけでは判定しない。
角速度は点群時刻を挟む履歴から補間し、絶対角速度を台形積分する。
EKFのchild frameと車体座標の回転関係を確認し、必要なら角速度を車体座標へ変換する。
角速度履歴が覆わない期間を推測で埋めず、その期間を蓄積から外す。
最新スキャン単体の幅は短縮できないため、窓の下限だけで精度を保証しない。

新しいスキャンごとに候補点群を作るが、出力頻度は `max_output_rate_hz` [Hz]で制限する。
処理待ちを無制限にためず、未処理の古い候補を捨てる。単発点群は独立して診断に残す。
処理周期とスキャン頻度を測定して決め、10 Hz出力を必須条件にはしない。

### 点群が不足する場合

点数を診断する。首振り角度の広がり・無効点の割合の追加診断は採用前の拡張項目とする。
点数だけでは形状の豊富さを保証できないため、照合の対応点率・残差も別に確認する。
旋回中に点群が不足しても、上限を超えて古い点を足さない。
最低条件を満たさなければその更新の照合入力を出さず、診断を異常にする。
「旋回時にも照合を継続する」は正常入力時の目標であり、無効な点群を必ず採用する意味ではない。

地面分離には別の蓄積出力を使い、必要な首振り範囲を確保する。
初期実装では既存の地面分離用経路を維持し、照合用の窓短縮を地面分離へ波及させない。
地面点の除去で地図作成と位置推定の入力条件が変わる場合は、同じ選別を両方に適用する。

### 設定値の決め方

| 設定 | 決定方法 |
|---|---|
| `max_window_s` | 首振り周期、必要な形状、遅延を比較。現在の2 sを基準実験とする |
| `max_turn_span_rad` | 旋回角速度と点群歪み・対応点率の関係から決定 |
| 旋回時の比較窓 | 0.5 sなどを実験条件に含める。採用値とはしない |
| 点数・角度範囲の下限 | 単発点群、部分蓄積、一往復の点群を同じ記録で比較 |
| voxel幅 [m] | 距離別の形状保持と処理時間から決定 |
| 出力頻度 [Hz] | 実時間・シミュレーション時間の両方の遅延を測定して決定 |

設定は正の有限値を基本とし、上限・下限の逆転は起動エラーにする。
計測に基づく値と、比較実験用の値を設定ファイルで区別する。

## 6. RTAB-MapとEKFの設定方針

RTAB-Mapの点群・オドメトリ入力、照合方式、フィルタ、自由度を比較条件として揃える。
初期評価は平坦路で平面の位置と向きに限定する。実機設定へ無条件に平面制約を適用せず、
傾斜路のroll・pitchを含む評価を別に行ってから3次元運用の採用を決める。
IMUのyaw角速度が正しいことと、絶対方位が正しいことを区別する。

EKFの角速度誤差を検証してから、車輪とIMUの共分散を調整する。
旋回時の車輪滑りが観測される場合は車輪のyaw角速度の重みを下げる候補とする。
IMU断・無効値・遅延時にもIMUを優先し続ける設定は採用しない。
LiDARで求めた位置を同じEKFへ戻さず、点群補償と照合結果の循環を避ける。

`Icp/MaxRotation` [rad]と `Icp/MaxTranslation` [m]は、移動予測からの追加補正の採用上限であり、
センサの重みを連続的に変える係数ではない。
入力点群とTFの整合を確認した後、対応点率・補正量・照合失敗率を記録して決める。
初期位置の再推定に必要な補正まで拒否する可能性があるため、通常追跡と再位置推定を分けて評価する。

初期実装では、角速度に応じたRTAB-Mapパラメータのオンライン変更を導入しない。
変化させるのは共通ノードの蓄積幅とし、因果関係を切り分ける。
重複する移動窓の点群は独立した測定ではない。更新頻度の増加を信頼度の増加として扱わず、
窓が重なる割合・オドメトリ共分散・姿勢補正の振動も評価する。

## 7. 欠測・異常時の動作

| 状態 | 点群処理と診断 |
|---|---|
| 計測時刻のTFが未着 | 有限時間待ち、期限を超えれば対象スキャンを破棄。最新TFで代用しない |
| TFの配信元が重複 | 評価を中断し、配信元を整理する |
| サーボ角の履歴不足・無効値 | スキャンを破棄し、補間範囲と棄却数を記録 |
| EKFの角速度が古い・無効 | 複数スキャンの蓄積を停止し、有効な単発点群だけを候補とする |
| 単発点群でもTF・角度が無効 | 照合入力を出さない |
| 時刻の逆行・センサ再起動 | 未処理点群と履歴をクリアし、履歴が揃ってから再開 |
| 古い・重複stampの入力 | 再使用せず、回数と時刻差を診断 |
| 処理時間が更新間隔を超過 | 古い候補を捨て、頻度・点数を見直す。stampを変更して隠さない |
| 照合失敗・長時間の更新停止 | 最後の地図補正と局所オドメトリだけでは測位品質を保証できないことを通知 |

蓄積ノードから速度指令は出さない。自律走行の継続可否は別の監視機能が担当する。
地図補正を保持したTFが出ていることだけで、自己位置推定が正常とは判定しない。
実機の自律運用へ採用する前に、最終成功時刻と品質を使う停止・復帰条件を定義する。
既存Nav2にその停止が実装されているとは仮定しない。

## 8. 検証と採用判定

### 記録する入力・結果

`/scan`、`/servo_state`、生IMU、EKF入力の車輪オドメトリ、EKF出力、`/tf`、`/tf_static`、
生の `/points`、照合用点群、RTAB-Mapの `/info`・`/mapGraph`、診断、走行指令を記録する。
シミュレーションでは `/clock` とGazeboの実際の機体姿勢も記録する。
`/tf_gazebo` の差動駆動オドメトリを真値とみなさず、世界座標の実姿勢を検証専用に取得する。
検証用真値は、EKF・点群補償・RTAB-Mapの入力に接続しない。
QoSの耐久性を含めて静的TFがbagに収録・再生されることを確認する。
同じ時刻源で再生し、実機ノードとbag再生を同じROS Domainで同時実行しない。

### 比較する構成

| 構成 | 目的 |
|---|---|
| スキャンごとの点群 | 現在の実機経路を基準にする |
| 固定時間の蓄積 | 現在のシミュレーション経路との差を確認する |
| 角度変化で制限する移動窓 | 旋回時の歪み・照合失敗を減らせるか確認する |

各比較で取付寸法、点時刻、voxel幅、地図、RTAB-Map設定を揃える。
地図作成と保存済み地図での自己位置推定を別試験とし、比較用DBのコピーを使う。
初期位置を意図的にずらした再位置推定も別に評価する。
既存DBを自動削除せず、新構成の地図との互換性を性能だけから仮定しない。

### 試験順序

1. 静止して首振り：取付寸法、サーボ中央角、符号、角度遅延、上下往復での形状差を確認。
2. 首振りを水平で固定して左右旋回：車体yaw、点時刻、IMU・EKFと真値の差を確認。
3. 首振りと左右旋回を同時実行：単発点群と蓄積点群の歪みを比較。
4. 一定速直進、発進・停止、直進から旋回・直進への遷移、左右切返しを比較。
5. 木や壁が少ない場所、傾斜路、IMU・サーボ状態・TFの欠落、負荷増加、時刻逆行を試験。

Gazeboでは静止姿勢・一定旋回・首振りの解析値を使った入力も生成し、
時刻ずれ・ジッタ・取付誤差を個別に注入する。
実機の計測期間を再現する合成スキャンは各ビームの時刻の機体・関節姿勢から生成する。
同時刻スキャンのstampをずらすだけでは走査中の歪みを再現した試験としない。
実機の受信遅延・サーボ追従差を含むbagで再評価するまで、移植可能性を確定しない。

### 評価指標と合格条件

| 指標 | 評価方法 |
|---|---|
| TF・計測時刻の整合 | 各点群の参照時刻でのTF取得率、欠測・重複・逆行、角速度の符号・時間差 |
| 点群の歪み | 既知の壁の厚み・二重化、木の幹の広がりを距離別に測る |
| 局所移動誤差 | 短区間の相対位置 [m]・相対角度 [rad]の誤差 |
| 地図上の位置誤差 | 真値または独立した基準に対する位置 [m]・角度 [rad]の誤差 |
| 照合の成立 | 成功更新率、連続失敗時間 [s]、対応点率、追加補正量 |
| 性能 | 入力から出力までの遅延、処理時間、p50/p95、メモリ上限、点群出力頻度 |
| 直進の維持 | 同じ直進データで基準構成に対する誤差・失敗率・遅延を比較 |

軌跡は最初の姿勢で座標を合わせ、評価途中で合わせ直して誤差を消さない。
実機で独立した基準がない試験は、形状整合・再現性の評価として扱い、絶対精度を主張しない。

許容位置・角度誤差、連続失敗時間、遅延、直進時の悪化許容幅は、必要な通路余裕と
停止・制御周期から試験前に数値化する。未確定のまま実機採用を承認しない。
候補構成は、旋回時の誤差・連続失敗を減らし、直進時の悪化が許容幅以内で、
両環境の同じ処理経路が時間・メモリ制限を満たした場合に採用候補とする。

## 9. 実装の分割

| 段階 | 作業 | 次へ進む条件 |
|---|---|---|
| A | TF平滑化を外す。比較用launch・設定と記録手順を用意 | TF配信元が一意、単発点群とEKFの時刻・座標が一致 |
| B | TF・点時刻・サーボ遅延の診断、解析入力のテスト | 静止首振りと固定首振り角での旋回の誤差を説明できる |
| C | 共通の `motion_cloud_assembler` と単体テスト | 座標変換、角度上限、左右切返し、欠測、時刻逆行、メモリ上限が仕様どおり |
| D | simulationと実機launchから同じノードを使用 | 同じbagで比較でき、地面分離への副作用がない |
| E | RTAB-Mapの採用条件、EKF共分散、時刻校正を調整 | 採用指標を満たし、再位置推定と異常復帰も確認済み |

実装先は `nodding_lidar` の `include/`・`src/`・`config/`・`launch/`・`test/` を基本とする。
Gazeboの入力変換と真値取得は `simulation` に置く。
共通ノードのtopic名・frame・設定値はパラメータ化し、実機の装置名やGazeboの依存を持ち込まない。
機器時刻の同期とサーボ実測角の取得は、測定結果に応じて必要な段階で追加する。

## 10. 実装と残る検証

- 共通蓄積：`motion_window.hpp` と `motion_cloud_assembler.cpp`。
- 共通起動・設定：`matching_cloud_launch.py` と `config/motion_cloud.yaml`。
- 実機接続：`slam_launch.py` と `bringup_launch.py enable_rtabmap:=true`。
- シミュレーション接続：3D地図作成・自己位置推定・点群蓄積の診断段階。
- 時刻・欠測の試験：`test_motion_window.cpp` と `test_motion_cloud_ros.py`。
- 未実施：サーボ追従遅れと点時刻の実測校正、真値を使う旋回・直進の精度比較、異常時の自律走行停止機能。

単発点群との比較は `max_scans: 1`、時間幅固定との比較は十分大きい
`max_turn_span_rad` を指定した設定ファイルで行う。固定時間の比較でも角速度履歴が
欠ければ単発に退避するため、健全な履歴を使って蓄積幅だけを比較する。
